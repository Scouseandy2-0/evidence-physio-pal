# PhysioSidekick — independent beta test script

Audience: a small mix of physiotherapists, FCPs and students once access is intentionally granted. This document prepares the work; no participation or review is implied.

Use fictional notes. Observe the first attempt before explaining a feature. Record time, success, assistance needed, confusion and the participant’s words. Ask permission before recording a session; no recording is required.

| Task | What the participant does | What to observe |
|---|---|---|
| First visit | Explain the app’s purpose and find the first-use guide | Is the educational scope clear? Can the guide be dismissed and reopened? |
| Discover | Search knee osteoarthritis; apply a publication/date filter | Are filters and relevance understandable? Does a slow request recover or give a useful original-source route? |
| Verify | Open a result’s PubMed/publisher page | Do PMID, DOI, title, authors and date correspond? Do they distinguish source access from evidence quality? |
| Read | Compare an indexed abstract with the original record; test a record without an indexed abstract | Are not-loaded, failed and not-indexed states distinct? Does anyone assume the abstract is an AI summary or the full paper? |
| Keep | Save a paper, create a collection and add fictional notes | Can they find it again after reopening? |
| Appraise | Record reading basis, question, findings, uncertainty and next step | Can they do so without an automatic grade? Is a suitable study-specific checklist still needed? |
| Reflect | Create a linked CPD reflection with actual reading time and a follow-up date | Is the difference between logging an activity and accreditation clear? |
| Reuse | Make one source-linked revision question and a short teaching plan | Do exports retain the paper reference and declared reading basis? |
| Anatomy | Find a scaphoid and femur, rotate/focus and follow the research link | Are side/orientation/selection clear? Does the user understand missing systems and pending expert review? |
| Devices | Save on one device, load/refresh the same account on the other | Did work persist? Is the account-save badge truthful? |
| Recovery | In a controlled test account, interrupt a save; make conflicting edits; review and combine | Is each version recoverable? Does combining restore previously removed records as disclosed? |
| Backup | Export, retain the original file, preview an import and confirm a merge in a test account | Are counts, limitations and effects clear? Are current pending edits preserved? |
| Access | Use keyboard only, largest text, zoom and VoiceOver | Can they perceive/focus/operate controls and dismiss dialogs? Any horizontal scrolling or content obscured by navigation? |
| Feedback | Prepare a fictional problem report, review it and copy it | Do they understand that it is not automatically sent? Is unnecessary private information absent? |

## Questions after the tasks

- Which task would you return to use next week, and why?
- What did you expect that the app did not do?
- Which information would you still verify elsewhere?
- What could you remove without affecting your use?
- What would a paid version need to provide consistently before it justified a fee?

Record findings as: date/release; participant role (no name needed in the issue log); device/browser; task; expected; observed; severity; evidence; fix; retest. Separate product usability from a clinical/anatomical accuracy review.
